# Skill: Database Migrations

## Purpose
Patterns and commands for creating, reviewing, applying, and rolling back Alembic migrations in the Order Tracking project.

## Golden Rules
1. **Never edit** an existing migration file — always create a new one
2. Always **review** the autogenerated file before applying — Alembic misses some things
3. Migration names: `snake_case` describing what changed
4. Test locally before pushing to CI

## Workflow — Adding a Column or Table

```bash
# Step 1: Make the change in the SQLAlchemy model
# e.g., add `notes` column to Order in app/models/order.py

# Step 2: Autogenerate migration
alembic revision --autogenerate -m "add_notes_to_orders"

# Step 3: Review the generated file in alembic/versions/
# Check: correct table name, correct column type, correct nullable/default
# Common Alembic blind spots:
#   - It won't detect RENAMED columns (generates drop + add instead)
#   - It won't detect server_default changes on existing rows
#   - Enum type changes need manual handling on PostgreSQL

# Step 4: Apply locally
alembic upgrade head

# Step 5: Verify
alembic current   # should show new revision as head
python -c "from app.models.order import Order; print(Order.__table__.columns.keys())"

# Step 6: Commit BOTH the model change AND the migration file
git add app/models/order.py alembic/versions/xxxx_add_notes_to_orders.py
git commit -m "feat: add notes column to orders"
```

## Rollback

```bash
# Roll back one migration
alembic downgrade -1

# Roll back to a specific revision ID
alembic downgrade abc123de

# Show current state
alembic current

# Show full history
alembic history --verbose
```

## Common Migration Patterns

### Add a nullable column (safe)
```python
def upgrade() -> None:
    op.add_column("orders", sa.Column("notes", sa.Text(), nullable=True))

def downgrade() -> None:
    op.drop_column("orders", "notes")
```

### Add a NOT NULL column with default (must backfill existing rows)
```python
def upgrade() -> None:
    # Step 1: add as nullable
    op.add_column("orders", sa.Column("priority", sa.Integer(), nullable=True))
    # Step 2: backfill
    op.execute("UPDATE orders SET priority = 0 WHERE priority IS NULL")
    # Step 3: set NOT NULL
    op.alter_column("orders", "priority", nullable=False)

def downgrade() -> None:
    op.drop_column("orders", "priority")
```

### Add an index
```python
def upgrade() -> None:
    op.create_index("ix_orders_priority", "orders", ["priority"])

def downgrade() -> None:
    op.drop_index("ix_orders_priority", table_name="orders")
```

### Add a PostgreSQL enum type
```python
order_status_enum = postgresql.ENUM(
    "pending", "confirmed", "processing", "shipped",
    "out_for_delivery", "delivered", "cancelled",
    name="orderstatus",
)

def upgrade() -> None:
    order_status_enum.create(op.get_bind())
    op.add_column("orders", sa.Column("status", sa.Enum(name="orderstatus"), nullable=False))

def downgrade() -> None:
    op.drop_column("orders", "status")
    order_status_enum.drop(op.get_bind())
```

### Rename a column (Alembic does NOT autogenerate this)
```python
def upgrade() -> None:
    op.alter_column("orders", "old_name", new_column_name="new_name")

def downgrade() -> None:
    op.alter_column("orders", "new_name", new_column_name="old_name")
```

## CI Check — Detect Missing Migrations

```bash
# Fails if any model change doesn't have a corresponding migration
alembic check
```

Add to CI before running tests:
```yaml
- run: alembic check
```

## Model Convention Reminders

- Primary keys: `str(uuid4())` except Order which uses `ORD-YYYYMMDD-XXXXX`
- Timestamps: `server_default=func.now()` and `onupdate=func.now()` — never set manually
- Soft deletes: `deleted_at: Mapped[datetime | None]` — no hard DELETE on Orders or Customers
- Enums: Python `enum.Enum` with string values matching the DB enum type
